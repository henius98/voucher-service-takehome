## Antigravity

Acquire pessimistic row lock on campaign during redemption to serialize concurrent stock checks and decrements.

### Cause

Concurrent transactions read identical in-memory `remainingStock` before prior commits. Both pass `campaign.getRemainingStock() <= 0`, claim vouchers, and overwrite stock with stale decrements, causing lost updates and negative stock.

## Antigravity

### Changes

1. [`CampaignRepository.java`](file:///home/henius/Downloads/voucher-service-takehome/voucher-service/src/main/java/com/prizm/campaign/repository/CampaignRepository.java#L15-L17): Added `decrementStock` query:
   ```java
   @Modifying(clearAutomatically = true)
   @Query("UPDATE Campaign c SET c.remainingStock = c.remainingStock - 1 WHERE c.id = :id AND c.remainingStock > 0")
   int decrementStock(@Param("id") Long id);
   ```
